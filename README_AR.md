# OMDA — تطبيق ويندوز

مشروع Electron مستقل داخل هذا المجلد. يستعمل نفس مصدر واجهة `../Frontend-System` أثناء البناء؛ لا ينسخ الصفحات إلى مصدر ثانٍ. التطبيق المثبت يحتوي الواجهة كاملة، ولا يحتاج وجود مشروع الويب أو Node.js أو Python على جهاز الموظف. يتصل بنفس API الذي اعتمده المستخدم:

`https://web-production-4e786.up.railway.app/api/`

## النسخة الحالية

نسخة تجريبية 0.3.0، Windows x64، بنوافذ متعددة وحساب غرفة مستقل وقوائم Alt أصلية. مثبت NSIS باختيار مكان التثبيت. دليل الاختصارات والقدرات والفحوص في [WINDOWS_FEATURES_2026_11_09_AR.md](WINDOWS_FEATURES_2026_11_09_AR.md). ملف التثبيت في:

`artifacts/OMDA-Setup-0.3.0-x64.exe`

المثبت غير موقّع رقميًا حاليًا. قد يعرض Windows تحذير ناشر غير معروف؛ توقيع الإصدار وقناة التحديث التلقائي لم يُجهزا. لا يُثبت التطبيق أو يُنشر تلقائيًا أثناء البناء. `runAfterFinish=false` يمنع تشغيله بعد التثبيت دون اختيار المستخدم.

قسم المطعم الجديد يحتاج نشر الباكند والواجهة معاً؛ راجع `../Backend-System/Backend/docs/RESTAURANT_2026_11_09_AR.md`.

## التشغيل والبناء

من داخل `Desktop-System`:

```powershell
npm ci
node node_modules/electron/install.js
npm run build:ui
npm start
```

يلزم تثبيت اعتماديات الواجهة المشتركة في `Frontend-Hotel-System` للبناء فقط (`npm ci` هناك). سكربت البناء يضمّن واجهة الويب الحالية داخل المثبّت. Electron 45 يتطلب Node.js 22.12 أو أحدث لأدوات التطوير.

```powershell
npm test
npm run pack
npm run dist
```

`pack` يجهز التطبيق غير المضغوط في `artifacts/win-unpacked`، و`dist` يبني مثبت ويندوز. الأوامر تمنع النشر التلقائي بـ`--publish never`. موارد Electron واعتمادياته تُضمّن في المثبت؛ ليس مطلوبًا تثبيتها على جهاز الموظف.

## الملفات

| المسار | الوظيفة |
|---|---|
| `desktop.config.json` | عنوان API العام المعتمد؛ لا كلمات مرور أو مفاتيح |
| `src/main.cjs` | نافذة التطبيق، الجلسة، القوائم، الملفات والطباعة والأذونات |
| `src/runtime.cjs` | التحقق من عنوان API وتقديم الملفات المضمنة وتقييد المسارات |
| `src/preload.cjs` | إعلام القوائم بتغيير لغة الواجهة فقط، بلا API للنظام داخل الصفحة |
| `scripts/build-ui.mjs` | بناء مصدر الويب إلى `renderer` دون تغيير إعدادات أو مجلد بناء الويب |
| `resources/icon.ico` | أيقونة OMDA المشتركة |
| `tests` | اختبارات runtime وقبول Electron |
| `renderer`, `node_modules`, `artifacts`, `.qa` | نواتج واعتماديات محلية مستبعدة من Git |

## الاتصال والجلسة

تُقدّم ملفات الواجهة المضمنة داخل جلسة Electron عند أصل عنوان الـAPI. طلبات `/api/` و`/media/` و`/private-media/` تذهب إلى السيرفر الحقيقي عبر شبكة Chromium مع TLS والكوكيز وCSRF المعتادة. لا يجري تعطيل `webSecurity` أو فتح CORS عام، ولا تُضاف خدمة باكند أو قاعدة بيانات محلية. هذا لا يجعل حسابات الفندق تعمل دون اتصال؛ واجهة التطبيق محلية والعمليات تحتاج السيرفر.

Access token يبقى بآلية الويب الحالية في الذاكرة، وrefresh cookie يبقى HttpOnly. ملفات جلسة التطبيق محفوظة في مجلد بيانات مستخدم Windows المعتاد، منفصلة عن Chrome. لا توجد كلمات مرور أو توكنات داخل ملفات المشروع أو المثبت. الواجهة sandboxed وNode integration معطل؛ فتح التطبيقات المحلية أو `file://` من روابط الصفحة مرفوض. فتح نسخة ثانية يعيد التركيز إلى النافذة الموجودة. حجم النافذة واللغة محفوظان.

القوائم تتبع لغة النظام، وتشمل الطباعة وSave PDF والتكبير. نوافذ تقارير الويب تبقى داخل التطبيق، والتنزيل يستخدم نافذة حفظ Windows. الكاميرا والموقع يتطلبان موافقة؛ لا يتجاوز التطبيق سياسة الدخول أو الدوام أو الموقع من السيرفر.

## اختبار محلي معزول

التجاوزات التالية للتطوير فقط، ولا تعمل لتغيير خادم المثبت النهائي:

```powershell
$env:OMDA_DESKTOP_API_URL='http://127.0.0.1:8000/api/'
npm start
```

HTTP مسموح للتطوير على loopback فقط. تشغيل القبول من جذر `Hotel System`:

```powershell
$env:HOTEL_TEST_DB='F:\Hotel System\.cache\desktop-acceptance.sqlite3'
$env:RUN_DESKTOP_QA='1'
$env:PLAYWRIGHT_MODULE='مسار حزمة playwright المثبتة'
./scripts/manage-backend.ps1 test hotels.test_desktop_browser_qa --noinput
```

القبول يستخدم قاعدة Django اختبارية وملفات ومجلد جلسة معزولة. يفحص تسجيل الدخول والكوكيز وتجديد الجلسة وإعادة تشغيل التطبيق والروابط الداخلية و36 عرضًا للواجهة (9 مسارات × لغتين × عرضي 1440/1024)، ونافذة تقرير الريفينيو الأصلية وPDF وCSV وتسجيل الخروج. لا يكتب حجوزات أو عمليات مالية على السيرفر المنشور.

الأجهزة الفعلية للطباعة والكاميرا والسكانر ودقة الموقع على كل جهاز Windows لم تُختبر بعد. توليد PDF وتنزيل الملف اختُبرا برمجيًا؛ التحديث التلقائي والتوقيع الرقمي وتجربة التثبيت/إلغاء التثبيت على جهاز موظف مستقل تبقى خطوات الإصدار التالي.

## إصلاح CSRF — 0.1.1

الإصدار 0.1.0 غير موصى به بسبب فقدان Origin عند تمرير الطلبات عبر protocol.handle. ظهر الخلل على HTTPS رغم نجاح النقل المحلي HTTP. الإصدار 0.1.1 يعيد Origin للتطبيق في طلبات API غير الآمنة لنفس الأصل عندما تكون مفقودة، ولا يستبدل أصلًا موجودًا أو رمز CSRF أو الكوكي. اختُبر على السيرفر المعتمد بطلب refresh مجهول: CSRF الصحيح يصل إلى رفض الجلسة الغائبة 401 بدل CSRF 403، وغياب رمز CSRF يبقى مرفوضًا 403. لم تستعمل كلمات مرور حقيقية أو عمليات فندقية. فحص الإنتاج الاختياري: node tests/csrf-production.cjs مع PLAYWRIGHT_MODULE، ولا يدخل ضمن npm test.

للتحديث أغلق التطبيق ثم شغّل مثبت 0.3.0؛ لا حاجة لحذف النسخة السابقة أو مجلد بياناتها. التوقيع الرقمي والتحديث التلقائي مؤجلان كما هو موضح أعلاه.
